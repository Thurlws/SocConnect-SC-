# Architecture

Checked against `main` at `e83c5c6` plus branch `phase-0-baseline`, 2026-10-15.

## Shape

- **Browser to database, directly.** React 19 with TanStack Router talks to Supabase (REST and RPC) using the signed-in user's token. Row-level security (RLS) decides what each user can read or write.
- **Reads:** one loader, `loadAppData` in `src/lib/api/fetch.ts` (22 queries), exposed through `useData()` in `src/lib/api/store.tsx`. It refetches every 15 s and on window focus (audit finding 5).
- **Writes:** SQL functions (`join_society`, `decide_membership`, `register_for_event`, `create_event`, `submit_support_request`, `schedule_meeting`, `share_recap`, …) or plain inserts checked by RLS. Errors become `{ ok, error }` via `act()` in `store.tsx`.
- **Server functions** (TanStack Start `createServerFn`), only where secrets are needed:
  - `src/lib/livekit.functions.ts`: call tokens, guest links (codes stored hashed)
  - `src/lib/calls.functions.ts`: AI recaps, Q&A, caption transcription
  - `src/lib/society-ai.functions.ts`: recommendations, "ask", collaboration proposals
  They authenticate with `requireSupabaseAuth` (Bearer token, `getClaims`). Some also use `supabaseAdmin` (service role, bypasses RLS).
- **Auth:** Supabase Auth email link from `src/routes/welcome.tsx`; Microsoft through Lovable's OAuth broker (`src/integrations/lovable`), whose setup is unverified. `src/lib/auth.tsx` holds session, profile and `my_access()` roles. Pages under `src/routes/_authenticated/` redirect signed-out visitors to `/welcome`.

## Database (`drizzle/migrations/`)

28 tables, about 38 SQL functions, RLS on every table.

| Migration | Adds |
|---|---|
| 0000 | Profiles, interests, roles (`platform_admin`), societies, committees, memberships, resources, invites; sign-up triggers `enforce_email_domain` and `handle_new_user` (INSERT only); `my_access()` |
| 0001 | Events, registrations, announcements, channels, messages, notifications, support requests, collaboration proposals, and their write functions |
| 0002 | Revokes execute on SECURITY DEFINER functions from `public` and `anon`. Signed-in users keep it (finding 3) |
| 0003 | Call rooms, participants, guest invites, recaps, `ai_usage`; nightly pg_cron job deletes transcripts after 7 days |
| 0004 | Tighter read policies via `society_visible()` and `can_see_profile()` |
| 0005 | Recommendation ranking, AI fit cache, `reserve_society_ai()` quota, AI availability state |
| 0006 | Official TU Dublin columns and 67 societies (generated by an external crawler) |

## Environments

- **Production:** Lovable Cloud (Supabase). Its public URL and key are in the committed `.env`. Lovable hosts the app and publishes from `main`. It holds real student data. There is no staging environment.
- **Local:** `dev/supabase/config.toml`, run with `bun run db:start`. It replays all migrations in filename order, and Mailpit at http://127.0.0.1:54324 catches emails. `bun run db:check-sign-in` checks the sign-in email paths.
- **CI:** `.github/workflows/ci.yml` runs typecheck, tests and build with Bun 1.4.2 and Node 24. Added in Phase 0; it hasn't run on GitHub yet.

## Gotchas

- Generated files: `src/integrations/**` (Lovable) and `src/routeTree.gen.ts` (TanStack). Don't edit them by hand.
- The root `supabase/config.toml` belongs to Lovable Cloud. The local stack uses `dev/supabase/config.toml`.
- `.env` is committed and must only hold public values. Locally, secrets go in `.env.local`, which TanStack Start loads into `process.env` for server code too. Production secrets live in Lovable Cloud.
- The Supabase CLI reads `SUPABASE_PROJECT_ID` from `.env`, so local Docker containers carry the production project id in their names. They are still local.
- Commits pushed to `main` sync into the Lovable editor. Never force-push or rewrite pushed history.
- `bun run lint` fails on about 2,497 pre-existing Prettier errors, so it's not in CI yet.
- TU Dublin is hard-coded in `src/lib/auth.tsx:6`, the 0000 domain trigger and staff-admin grant, `src/routes/welcome.tsx`, `src/routes/_authenticated/admin.tsx:103`, `src/lib/society-ai.functions.ts:6`, `src/components/profile-form.tsx` (`src/data/tud-courses.json`), `src/styles.css` and the `__root.tsx` meta tags. Phase 3 of the roadmap replaces this with a `universities` table.
- Tests (`src/test/`, 25 of them) cover helpers and rendering only. No test touches the database rules.
